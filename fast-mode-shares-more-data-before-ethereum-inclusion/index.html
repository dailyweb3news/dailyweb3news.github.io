Fast Mode Shares More Data Before Ethereum Inclusion

Does fast mode on a private RPC reduce transaction privacy? Yes: it reaches more builders and TEE searchers before inclusion, while staying out of Ethereum’s public mempool.

The Onchain Brief EditorsNov 26, 2026 · 08:22 UTC3 min read

Fast mode on a private RPC reduces recipient-level privacy before inclusion, because it shares a transaction with more parties than standard Flashbots Protect. It still keeps the transaction out of the public mempool.

What happens to a transaction in fast mode?

A signed transaction sent through the private RPC is multiplexed to registered builders within one block. Fast mode also shares its full transaction information with searchers in trusted execution environments (TEEs), secure computing environments designed to keep data protected.

Sending to more builders gives a builder assembling the winning block a better chance to receive and include the transaction promptly. For the wider speed-versus-privacy choice, Flashbots’ fast mode trade-offs on Flashbots protection article explains how to weigh faster inclusion against a narrower recipient list.

The change is about who can see the signed transaction before it is mined. Standard Protect keeps it out of the public mempool; fast mode also gives registered builders and TEE searchers access before inclusion. That means less privacy from those recipients, even though the transaction remains private from public mempool observers.

Once included, the transaction’s contents are public on Ethereum, whichever RPC mode sent it. Fast mode changes the path and the pre-inclusion audience, not the visibility of the mined transaction.

What changes when you send a swap?

With a swap sent through standard Protect, the transaction stays outside the public mempool while it is pending. In fast mode, the same signed swap is sent to registered builders and its full details are shared with TEE searchers. The wider set of recipients creates more possible paths into the next block, while the public-mempool protection remains.

This is an illustrative example: imagine you submit a swap and want it included promptly. Fast mode sends it to more builders, so the builder producing the winning block has a better chance of seeing it in time. The cost is that more parties can access its details before inclusion. You are choosing between faster propagation and a smaller set of recipients, not between private and public mempool submission.

That distinction matters if you are deciding how to send an ordinary swap. Use the mode that fits your priority: fast mode broadens access to improve the chance of prompt inclusion, while standard Protect keeps the pre-inclusion recipient set narrower. Neither mode hides transaction contents after they are recorded on Ethereum.

Related

Does Flashbots fast mode send transactions to the public mempool?

No. It shares transactions with registered builders and TEE searchers, while keeping them out of the public mempool.

What does fast mode share with searchers?

Fast mode shares full transaction information with searchers operating inside TEEs.
